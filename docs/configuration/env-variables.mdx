Shumai is configured via environment variables. You can define these variables in a `.env` file at the root of your application workspace, or pass them directly to your Docker containers.

---

## Database Config

| Variable       | Description                                                                                | Example / Default                                        |
| :------------- | :----------------------------------------------------------------------------------------- | :------------------------------------------------------- |
| `DATABASE_URL` | PostgreSQL connection URL. Must target a database with the `pgvector` extension installed. | `postgresql://user:pass@localhost:5432/db?schema=public` |

## Server Config

| Variable                | Description                                                                                       | Example / Default |
| :---------------------- | :------------------------------------------------------------------------------------------------ | :---------------- |
| `SHUMAI_SERVER_PORT`    | The port on which the Shumai web server will listen.                                              | `3000` (default)  |
| `MAX_REQUEST_BODY_SIZE` | Maximum allowed size for request bodies (e.g., for large file uploads). Default is 10GB in bytes. | `10737418240`     |

## Authentication & Application Config

| Variable             | Description                                                                                                      | Example / Default                                                |
| :------------------- | :--------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------- |
| `BETTER_AUTH_SECRET` | A secure, random 32-byte secret used to sign session cookies and JWTs.                                           | Generate with `openssl rand -base64 32`                          |
| `BETTER_AUTH_URL`    | The public URL of your Hono backend API. Used for redirect flows and notification email links fallback.          | `http://localhost:3000` (respects `SHUMAI_SERVER_PORT` fallback) |
| `APP_URL`            | The public URL of the web application. Used for notification email deep links (falls back to `BETTER_AUTH_URL`). | `https://shumai.example.com`                                     |

## Storage Config

Shumai supports storing files locally or on S3-compatible endpoints.

| Variable                   | Description                                                                                                                                             | Example / Default                                                         |
| :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------ | :------------------------------------------------------------------------ |
| `STORAGE_BACKEND`          | Storage type. Use `local` for local file system storage, or `s3` for S3-compatible cloud storage.                                                       | `local` (default) or `s3`                                                 |
| `AWS_ENDPOINT_URL_S3`      | Endpoint for S3 storage or local storage. Used by the browser to build file upload URLs. Must include port if deploying remotely or using custom ports. | `http://localhost:3000` (respects `SHUMAI_SERVER_PORT` fallback if unset) |
| `S3_BUCKET`                | S3 bucket name.                                                                                                                                         | `shumai` (default)                                                        |
| `S3_ACCESS_KEY_ID`         | Access key credentials for S3.                                                                                                                          | `minioadmin` (default)                                                    |
| `S3_SECRET_ACCESS_KEY`     | Secret key credentials for S3.                                                                                                                          | `minioadmin` (default)                                                    |
| `S3_REGION`                | S3 storage region.                                                                                                                                      | `auto` (default)                                                          |
| `PRESIGNED_URL_EXPIRES_IN` | Number of hours for which generated presigned download/upload links are valid.                                                                          | `5` (default)                                                             |

### Local Storage Port Configuration

When `STORAGE_BACKEND` is set to `local` (default):

- `SHUMAI_SERVER_PORT` configures the port on which the Shumai web server starts and listens.
- `AWS_ENDPOINT_URL_S3` configures the public/external endpoint used by client browsers to upload and download files. It must include the scheme and port.

For example, if you deploy Shumai on a remote server at `http://123.456.7.8` and configure port mapping `12345:3000` (exposing port 3000 internally as port 12345 externally) in Docker Compose:

- Set `SHUMAI_SERVER_PORT` to `3000`.
- Set `AWS_ENDPOINT_URL_S3` to `http://123.456.7.8:12345`.

### Storage Catalog

| Variable                  | Description                                                                                                                                              | Example / Default |
| :------------------------ | :------------------------------------------------------------------------------------------------------------------------------------------------------- | :---------------- |
| `STORAGE_CATALOG_ENABLED` | Keep a record of every project, folder, file, metadata field and metadata value in storage under `catalog/`, updated within a few seconds of any change. | `false` (default) |

Your files are stored under their original names, but which project and folder each file belongs to, its metadata and its trash state live only in the database. With the catalog turned on, that information is also kept in storage next to the files, so the library can be rebuilt if the database is lost.

The catalog is compact: each few seconds' worth of changes is written as one small compressed file in `catalog/log/`, and from time to time the whole library is written as one compressed snapshot in `catalog/snapshot/`, replacing the log files before it. Tagging thousands of files at once writes a handful of small files, not thousands. To restore:

1. Start Shumai with a new, empty database and create a team (and your user) as usual.
2. Check what would be restored: `shumai restore-catalog --team <teamId> --dry-run`
3. Restore: `shumai restore-catalog --team <teamId> --creator <userId>`

The restore recreates projects, folders, files, metadata fields and values, and trash state, reusing the files and previews already in storage. It skips anything that already exists, so it is safe to run again. Comments, members, share links and settings are not part of the catalog; keep regular database backups for those. The catalog only helps if storage survives when the database does not, so keep them on separate disks or services.

### Checking the catalog and your files

Each file's SHA-256 fingerprint is computed in the background shortly after its upload is confirmed (files uploaded before this was added have none yet, and neither do files still waiting in the hashing queue when the server stops) and is kept in the catalog. Hashing reads the stored file once, two files at a time; set `CONTENT_HASH_CONCURRENCY` to change that number. `shumai verify-catalog` compares the catalog with what is actually in storage, without changing anything:

- `shumai verify-catalog` checks that every file the catalog lists exists in storage and has the recorded size.
- `shumai verify-catalog --deep` also reads every file and compares its fingerprint, which catches silent corruption. It reads your whole library, so run it off-peak.
- `--json` prints a machine-readable report instead of the summary, `--concurrency <n>` sets how many files are checked at once (default 2, to keep the server responsive), and `--deep --backfill-hashes` records the fingerprint of files that do not have one yet.

The command exits with 0 when everything matches, 1 when it finds a problem (a missing file, a different size or fingerprint, or an unreadable catalog object), and 2 when it could not run. It only needs storage, so it works even if the database is gone.

## Workflow Config

Configures whether background transcoding and AI agents are executed locally or offloaded to a Temporal cluster.

| Variable                   | Description                                                                                        | Example / Default               |
| :------------------------- | :------------------------------------------------------------------------------------------------- | :------------------------------ |
| `WORKFLOW_EXECUTOR`        | Engine choice. Use `local` for in-process database polling, or `temporal` for distributed workers. | `local` (default) or `temporal` |
| `TEMPORAL_ADDRESS`         | Host and port of the Temporal cluster gRPC service.                                                | `localhost:7233` (default)      |
| `EMBEDDING_CHUNK_DURATION` | The duration in seconds for each video chunk when generating video embeddings.                     | `60.0` (default)                |
| `EMBEDDING_CHUNK_OVERLAP`  | The duration in seconds to overlap video chunks when generating video embeddings.                  | `5.0` (default)                 |

## Sandbox Config

| Variable                       | Description                                                                                            | Example / Default |
| :----------------------------- | :----------------------------------------------------------------------------------------------------- | :---------------- |
| `ENABLE_WEAKER_NESTED_SANDBOX` | Enables weaker nested sandbox mode for environments without user namespace permissions (e.g., Docker). | `false` (default) |

## Logging Config

| Variable     | Description                                                                                          | Example / Default |
| :----------- | :--------------------------------------------------------------------------------------------------- | :---------------- |
| `LOG_LEVEL`  | Pino logging level. Options: `debug`, `info`, `warn`, `error`.                                       | `info` (default)  |
| `LOG_FORMAT` | Log format style. Use `json` for production logging, or `pretty` for human-readable terminal output. | `json` (default)  |
