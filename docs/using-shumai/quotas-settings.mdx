AI workflows and media processing tools can consume significant compute and API credits. Shumai provides a **Resource Quotas** system that allows Team Owners to set granular rate limits, govern budgets, and monitor real-time usage across team members and roles.

---

## Overview

Resource Quotas allow you to define maximum usage limits across specific time windows (e.g., hourly, daily, or weekly). When a member or team reaches their assigned quota, further actions for that resource are safely blocked until the quota period resets.

Quota configuration and usage monitoring are separate parts of the team experience:

- To create and manage quota rules, open **Team Settings** and navigate to the **Quotas** tab.
- To monitor live usage, open the **Team Dashboard** and select **Quotas** under the **TEAM** section.

The quota dashboard is available to Team Owners.

---

## Scope Modes

When creating or editing a quota rule, you can define how the limit is applied:

### 1. Each Member

- **Behavior**: Every member in the scope receives their own independent limit. Usage by one member does not affect the remaining quota of others.
- **Optional Role Filter**: You can restrict the quota to members with a specific role (e.g. only **Editors** or **Reviewers**), or apply it to the entire team.
- **Use Case**: Give each editor a daily budget of 100,000 tokens.

### 2. All Members (Shared Pool)

- **Behavior**: The quota limit is shared as a collective pool across all matching members. Every member's consumption draws from the same total.
- **Optional Role Filter**: Apply the shared pool to all team members or restrict it to a specific role.
- **Use Case**: Cap the total team spending on AI models to $50 per day.

### 3. Selected Members

- **Behavior**: Assign individual limits to specific chosen team members.
- **Use Case**: Grant higher limits to senior artists or technical directors while keeping standard limits for others.

## Supported Resource Types

Shumai supports quota enforcement across multiple layers of the AI and agent architecture:

| Resource Type               | Description                                                                             | Target Specification                 |
| :-------------------------- | :-------------------------------------------------------------------------------------- | :----------------------------------- |
| **Total Tokens**            | Total LLM input and output tokens consumed in chat, comments, and autofill.             | Team, Role, or Members               |
| **AI Cost ($)**             | Dollar expenditure accrued from AI model providers.                                     | Team, Role, or Members               |
| **MCP Server Calls**        | Number of tool invocations directed to a connected Model Context Protocol (MCP) server. | Target MCP Server ID                 |
| **Sandboxed Bash Commands** | Shell commands executed by the agent inside the isolated sandbox.                       | Wildcard pattern (e.g. `npm *`, `*`) |
| **Agent Tool Calls**        | Calls to specific native tools (e.g. `analyze_image`, `screenshot`, `create_file`).     | Tool name                            |

### Bash Command Wildcard Matching

For sandboxed bash execution, you can restrict specific command patterns using wildcards (`*` and `?`):

- `*`: Matches any bash command execution.
- `npm *`: Matches any npm command (e.g., `npm install`, `npm test`).
- `git commit*`: Matches git commit invocations.

## Time Periods & Rollover

Quotas can be configured with the following reset periods:

- **1 Hour** (`1hour`)
- **5 Hours** (`5hour`)
- **1 Day** (`1day`)
- **7 Days** (`7day`)

### Lazy Reset Mechanism

Shumai tracks usage windows automatically. When a period window expires, the system resets the quota upon the member's next request, seamlessly starting a fresh window without requiring background maintenance tasks.

## Monitoring Live Usage

Team Owners can inspect live consumption from the team dashboard:

1. Open the **Team Dashboard**.
2. Select **Quotas** under the **TEAM** section.
3. Quota rules are shown as first-level collapsible entries.
4. Expand a rule to view its usage records.

Each usage record displays:

- **Consumption Status**: Progress bar showing consumed units versus the total limit.
- **Remaining Allowance**: Percentage and numerical amount remaining.
- **Refresh Countdown**: Remaining time until the active window resets (e.g., _"Refreshes in 45m"_).
- **Target**: The team shared pool, role pool, or individual member associated with the record.
- **Member Search**: For member-scoped rules, search the usage records by member name or email.

Usage records are loaded when a rule is expanded and refresh automatically while the rule is open.

### Manually Resetting a Usage Record

Each usage record includes a **Reset Usage** action. After confirming the action:

- Consumption is set to zero.
- The quota period starts immediately.
- The period ends after the configured quota duration.
- For example, resetting a one-day quota at 10:00 starts a new window from 10:00 until 10:00 the following day.

A reset can also initialize a zero-consumption record for a member or shared pool that has not received usage yet. Resets are recorded in the team audit log.

## Managing Quota Rules

- **Enable / Disable**: Toggle the switch on any quota card in Team Settings to temporarily pause or resume enforcement without deleting the rule.
- **Edit Rules**: Click any quota card in Team Settings to update limits, change reset periods, or adjust member selections.
- **Delete Rules**: Open the card action menu (`⋮`) in Team Settings and select **Delete** to remove the quota rule.

Quota usage is monitored and reset from the Team Dashboard rather than from the settings rule cards.
