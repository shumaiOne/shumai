Shumai makes it easy to bring creative media into your workspace. It supports standard file uploads, directory/folder structure preservation, and real-time upload progress indicators.

---

## Uploading Assets

You can upload files and folders in two ways:

1.  **Drag and Drop**: Drag files or entire folders directly from your system file explorer and drop them anywhere on the Shumai dashboard interface.
2.  **Upload Buttons**: Click on the **Upload File** or **Upload Folder** buttons in the top-right toolbar.

## Folder Uploads and Hierarchy

When you upload a folder, Shumai reads the directory structure and replicates it inside your project.

- New folders are created in the database as `AssetType.folder` assets.
- Nested files are linked to their parent folders using the `parentId` field.
- There is no depth limit for nested subfolders.

---

## Asset Status Lifecycle

Once an upload is initiated, the asset moves through the following database statuses:

- `uploading`: The file chunks are actively being sent to the S3-compatible or local storage backend. The UI displays a progress bar indicating percentage completion.
- `uploaded`: The storage transfer is complete.
- `processing`: Shumai has queued background tasks for the asset. This includes extracting media metadata (resolution, codec, duration) and generating proxy files (transcoding) for web playback.
- `processed`: The file metadata is fully populated, transcoding is complete, and the asset is ready for viewing, search, and collaboration.
- `trashed`: The asset has been deleted by a user but is kept in the trash bin before permanent purging.

---

## Storage Backends

Depending on your configuration:

- **Local Storage (`STORAGE_BACKEND=local`)**: Files are uploaded and stored directly on the host machine running Shumai.
- **S3 Storage (`STORAGE_BACKEND=s3`)**: Files are uploaded directly to your S3 bucket (e.g. Cloudflare R2, MinIO, AWS S3) via presigned URLs generated by the API, minimizing load on the Hono backend server.
