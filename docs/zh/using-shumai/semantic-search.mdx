传统搜索依赖字符精确匹配（例如：搜索 "dog" 无法找到名为 `golden_retriever.jpg` 的文件）。Shumai 通过 **语义搜索** 解决了这一痛点，支持对文件的概念与深层语义建立索引。

---

## 语义搜索原理

语义搜索将文本查询词与文件内容转化为概念特征档案，使相似的构思与视觉画面在向量空间中邻近排列。

1. **索引生成**：上传媒体资产时，Shumai 后台智能体将扫描文件的视觉元素、文本内容或描述信息，并转化为概念特征档案。
   - **多模态向量模型服务**：Shumai 支持两类模型服务：
     - **EmbeddingGemma 2（本地）**：由 `shumaiOne/embedding-server` 驱动，生成 768 维多模态向量，完全离线运行。视频按每个 60 秒分块以 **每分钟 15 帧**（非标准宽高比为 14 帧）采样。详见 [向量模型服务配置指南](/zh/using-shumai/embedding-server)。
     - **Gemini Embedding 2（云端）**：由 Google 的 `gemini-embedding-2` API 驱动，生成 1536 维向量。视频切分为 60 秒片段（去除音频，按 1 fps 采样，每块最多 32 帧）。
   - **分块配置**：管理员可通过环境变量 `EMBEDDING_CHUNK_DURATION`（默认值：60s）与 `EMBEDDING_CHUNK_OVERLAP`（默认值：5s）自定义分块时长与重叠时间。
2. **概念匹配**：开启“语义搜索”（Semantic）开关后，Shumai 会比对查询词的概念含义与媒体资产的语义特征。
3. **检索结果**：例如搜索“海滩日落”，即使视频文件名为 `IMG_4029.mp4`，也能成功检索到黄昏海浪拍岸的视频。

### 理解搜索结果

语义搜索与传统的关键字过滤机制有所不同：

- **排序对比筛选**：语义搜索的表现更接近 **相关度排序** 而非严格的硬过滤。最相关的结果会优先置顶显示，但关联度较低的内容仍可能出现在列表后方（排名较低）。若需排除特定类型的文件，可配合 **筛选** 面板组合使用。
- **视频分块结果**：由于 Shumai 采用分块机制对视频建立索引，同一个长视频可能会在搜索结果中出现多次，每条结果对应匹配到概念的具体视频片段。
- **匹配时间戳**：当检索结果来自某个视频分块时，Shumai 会标出匹配的起止时间点。点击此类结果可直接打开视频并自动跳转到对应的时间戳位置。

## 启用语义搜索

若需使用语义搜索：

1. 确认团队管理员已在 **团队设置** > **智能体** 下启用了 **Embedding 智能体**。
2. 启用后，Shumai 将自动为新上传的文件建立索引。
3. 在文件管理器的搜索框旁开启 **语义**（Semantic）开关，即可按概念语义检索资产。
