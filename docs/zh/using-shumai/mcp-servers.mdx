模型上下文协议（Model Context Protocol，简称 MCP）是一套开放标准，支持 AI 模型安全对接外部工具、微服务与 API。在 Shumai 中，可通过标准 HTTP 传输协议（`Streamable HTTP` 或 `SSE`）注册远程 MCP 服务端，并将其分配给 AI 智能体。

---

## Shumai 中的 MCP 运作机制

为避免动辄数十个复杂的参数 Schema 挤占模型的上下文窗口，Shumai 采用了高能效的 MCP 连接架构：

- **自动发现与元数据缓存**：添加 MCP 服务端后，Shumai 会将其记录在团队配置中，并连接该端点以自动发现可用工具、服务端使用指引与描述元数据。在手动刷新服务端、完成 OAuth 鉴权或智能体首次调用其工具时，系统均会触发服务发现。这些 Schema 会缓存在数据库中，供后续秒级读取。
- **高上下文利用率的代理工具 (`mcp`)**：已分配的 MCP 服务端会通过注入对话智能体中的统一 `mcp` 代理工具实现多路复用。智能体可按需动态检查服务状态、检索工具、查看参数 Schema 并调用函数，无需预先消耗大量 LLM Token。
- **直连工具选项 (Direct Tools)**：对于高频调用的核心工具，可将其单独配置为**直连工具**，使其作为顶层 LLM 原生函数直接暴露给智能体，与 `mcp` 代理工具并行共存。

## 添加 MCP 服务端

在 Shumai 中注册新 MCP 服务端的步骤如下：

1. 前往**团队设置**并点击 **MCP** 标签页。
2. 点击**添加 MCP 服务端**。
3. 在弹窗中输入**服务端端点 URL**（例如 `https://mcp.example.com/sse` 或 `http://localhost:8080/mcp`）。
4. 点击**创建**。

> **注意：** 仅需提供**服务端端点 URL** 即可创建。Shumai 会根据 URL 自动生成占位服务名；当首次连接端点（通过编辑弹窗中的“刷新”按钮或智能体首次发起工具调用）时，系统会自动同步服务端的真实名称、运行状态、操作指引以及工具清单。

### 可选高级配置项

创建服务端后（初始弹窗仅需填入 URL），可打开编辑弹窗配置高级选项：

- **传输协议（Transport）**：在 `Streamable HTTP`（默认）与 `Server-Sent Events (SSE)` 之间选择。
- **认证策略（Auth Strategy）**：可选 `Auto-detect`（自动检测，默认）、`None`（无认证）、`Bearer Token` 或 `OAuth 2.0`。
- **最低权限角色（Minimum Permission Role）**：设置调用该服务端工具所需的最低团队角色要求（`Reviewer` 审阅者、`Editor` 编辑者或 `Owner` 所有者）。
- **直连工具（Direct Tools）**：指定需作为原生 LLM 工具直接呈现给智能体的工具名称列表。

## 理解工具配置机制

在服务端的编辑弹窗中，**工具（Tools）**列表展示了所有已发现的工具，每个工具均支持三态切换（同时提供**全部关闭** / **全部代理** / **全部直连**批量操作）：

- **关闭（Off）**：彻底排除该工具，对智能体完全不可见——既无法通过代理工具列出、搜索或调用，也无法注册为直连工具。适用于隐藏干扰项或高危工具。
- **代理（Proxy，默认）**：工具通过统合的 `mcp` 代理工具按需调用。
- **直连（Direct）**：工具以 `{server}_{tool}` 为前缀名称，作为顶层原生函数直接开放给智能体。

### `mcp` 代理工具

`mcp` 代理工具是注入智能体上下文的一个独立函数，它多路复用了分配给该智能体的所有 MCP 服务端。智能体无需在启动时一次性加载所有工具的完整参数 Schema，而是根据实际需要与服务端交互：

- `mcp({})` — 查看所有已分配服务端的连接与认证状态
- `mcp({ server: "name" })` — 列出指定服务端的可用工具
- `mcp({ search: "query" })` — 跨服务端检索工具（默认附带参数 Schema）
- `mcp({ describe: "tool" })` — 检视指定工具的完整参数 Schema
- `mcp({ instructions: "name" })` — 查看指定服务端的使用指引
- `mcp({ server: "name", tool: "tool_name", args: {...} })` — 调用工具（支持传入 `{server}_{tool}` 前缀名称或工具原名）
- `mcp({ action: "auth-start", server: "name" })` — 为指定服务端发起 OAuth 认证流程

由于上下文窗口仅被单个紧凑的工具（外加简短的服务端/工具列表）占用，即便服务端暴露数十个工具，代理模式依然能将 Token 开销降至极低。相应的权衡在于增加了一轮服务发现交互：智能体通常需要先列出或检索工具，随后再发起调用。

### 直连工具 (Direct Tools)

直连工具则采用了另一种权衡取舍。被设为**直连（Direct）**的工具会被注册为原生顶层函数（如 `tavily_mcp_tavily_search`），智能体能够像调用内置工具一样直接使用它。

直连工具的优势：

- **高频操作调用更快、更稳定**：完整的参数 Schema 始终驻留在上下文窗口中，智能体无需先通过代理发现，一步即可直接调用。
- **工具感知度更高**：模型能够预先感知工具功能及其描述，更容易在恰当时机自主选用该工具。

开销代价：每个直连工具的 Schema 都会常驻并消耗上下文 Token，因此建议仅将高频或关键工具设为**直连**，将接口繁多的庞大 MCP 服务端保持为**代理**模式以节省上下文。直连工具同样遵循基于角色的权限校验规则，且 `mcp` 代理工具仍可继续用于服务发现、鉴权与状态检查。

## 身份认证模式

Shumai 支持多种认证策略以保障 MCP 端点的安全访问：

### 1. 无认证 (`none`)

用于公开或本地运行且无需认证凭据的 MCP 服务端。

### 2. Bearer Token (`bearer`)

提供静态 API Token 或密钥。Shumai 会在所有传输请求的 `Authorization: Bearer <token>` 请求头中附带该令牌。

### 3. OAuth 2.0 (`oauth`)

面向受 OAuth 身份提供商保护的 MCP 端点：

- **授权码模式 + PKCE（Authorization Code + PKCE）**：在团队设置的服务端卡片上点击**连接**。Shumai 会弹出安全的 OAuth 授权窗口并跳转至身份提供商页面。确认授权后，浏览器会自动回调至 Shumai，完成令牌兑换并刷新服务端工具列表。
- **客户端凭据模式（Client Credentials）**：填入 `Client ID` 与 `Client Secret`，用于自动化服务间令牌获取。

## 为智能体分配 MCP 服务端

默认情况下，新添加的 MCP 服务端**未分配给任何智能体**。若需授权智能体访问 MCP 服务端：

1. 前往**团队设置** > **智能体**。
2. 点击目标智能体打开配置弹窗。
3. 向下滚动至 **MCP 服务端**区域。
4. 勾选希望授权给该智能体的 MCP 服务端开关。
5. 点击**保存修改**。

---

## 基于角色的访问控制 (RBAC)

每个 MCP 服务端均支持设置**最低权限角色**（`Reviewer` 审阅者、`Editor` 编辑者或 `Owner` 所有者）：

- 当智能体尝试调用 MCP 服务端上的工具时，Shumai 会校验当前与智能体交互的用户角色。
- 若用户角色未达到设定的最低门槛，工具执行将被拦截并返回权限不足的错误信息，杜绝越权操作。
