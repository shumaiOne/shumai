高分辨率摄影机格式与原生媒体文件无法在 Web 浏览器中直接播放。Shumai 在后台自动将视频资产转码为适用于网页的流式传输与预览格式。

团队所有者可在 **团队设置 > 视频转码** 页面自定义视频转码行为。

无论选择何种转码策略，Shumai 流水线都会**始终**为原始文件生成至少一个轻量级 `180p` 代理版本，以确保快速拖拽播放（Scrubbing）、缩略图生成与即时预览。

## 转码策略

**转码策略**卡片用于配置 MP4 视频转码以及 HLS 自适应流媒体。

### 播放与下载行为

Shumai 采用双格式交付策略：

- **未启用 HLS 时**：浏览器内视频播放与文件下载均使用生成的 MP4 文件。
- **启用 HLS 时**：浏览器内视频播放使用 HLS（HTTP Live Streaming）实现流畅的自适应码率播放，文件下载则使用生成的 MP4 文件。

<Warning>
  **存储用量提示**：启用 HLS 除生成标准 MP4 代理文件外，还会生成多码率切片文件（`.ts` /
  `.m4s`）及播放列表清单，这会显著增加存储桶的容量占用。
</Warning>

### MP4 转码

生成兼容 Web 的 MP4 文件，用于文件下载与标准视频播放。团队所有者可为上传的文件选择 MP4 转码模式：

#### 1. 最佳匹配 (Best Match)

- **工作机制**：Shumai 检测所上传视频的最长边尺寸，生成单一匹配或略低于源画质的最优分辨率，避免无谓的升采样（Upscaling）。
- **输出产物**：生成轻量级 `180p` 代理版本以及计算得出的最佳匹配 MP4 文件。
- **适用场景**：推荐默认选项。在保证广泛的播放与下载兼容性的同时，最大程度缩短处理耗时并节省存储空间。

#### 2. 多分辨率阶梯 (Multi Resolutions)

- **工作机制**：可指定生成的目标分辨率阶梯：`480p`、`720p`、`1080p`、`1440p` 与 `2160p`。系统仅生成不超过原始分辨率的画质（绝不对内容升采样）。
- **输出产物**：生成 `180p` 代理版本，以及所选且未超出源视频分辨率的所有分辨率文件。
- **适用场景**：适用于需要下载多种指定分辨率的场景（例如使用 720p 快速分发共享，使用 1080p 审阅）。

### HLS 流媒体

开启 **HLS 流媒体** 开关后，Shumai 会为上传的视频生成自适应码率 HLS 分发包：

- **分辨率阶梯**：配置 HLS 流媒体生成的目标分辨率（`480p`、`720p`、`1080p`、`1440p`、`2160p`）。系统仅生成不超过原始视频分辨率的阶梯。
- **播放器集成**：当 HLS 可用时，Web 播放器会自动采用 HLS 流式播放，并根据客户端网络带宽动态切换码率。

## 硬件加速

为将编码负载从 CPU 分流至 GPU，Shumai 支持硬件加速视频编码：

- **禁用（软件编码）**：使用标准 CPU `libx264` 软编器并配合恒定速率因子（CRF）。
- **自动检测**：自动探测并启用可用的 GPU / 硬件加速能力（NVIDIA NVENC、Intel QuickSync、AMD/Intel VA-API、Apple VideoToolbox、Rockchip RKMPP）。

详见 [硬件加速转码指南](/zh/configuration/hardware-transcoding)，获取 Docker Compose 配置、GPU 透传及驱动前置要求说明。

## FFmpeg 线程数

**FFmpeg 线程数** 滑块用于控制转码任务期间 FFmpeg 可调用的最大 CPU 线程数：

- **自动 (0)**：FFmpeg 根据宿主机可用 CPU 核心数自动选择最优线程数。
- **手动 (1 - 32)**：将 FFmpeg 限制为固定线程数，适用于在共享 Worker 节点上限制 CPU 资源占用。

## 处理架构

媒体转码属于高资源消耗型任务。管理员可根据扩缩容需求，选择在主服务器上直接运行转码引擎（单服务器模式），或将任务委派给专门的转码 Worker 节点（独立 Worker 模式）。

无论采用何种模式，负责处理的机器均须安装系统级媒体工具（`ffmpeg` 与 `ffprobe`）。关于搭建独立转码 Worker 的详细步骤，请参阅 [分布式部署指南](/zh/configuration/distributed)。
