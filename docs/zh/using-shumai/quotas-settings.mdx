---
title: 资源配额
description: 配置团队资源配额、实时监控用量并在仪表板中重置配额周期。
---

AI 工作流与媒体处理工具会消耗大量算力与 API 额度。Shumai 提供了**资源配额**（Resource Quotas）体系，使团队所有者能够设置精细化的用量限制、管控成本预算，并实时监控团队成员与角色的用量情况。

---

## 概述

资源配额支持在指定的时间窗口（如每小时、每天或每周）内设定最大用量上限。当成员或团队达到设定的配额时，系统将安全拦截针对该资源的后续操作，直至配额周期重置。

配额规则配置与用量监控在界面中相互独立：

- 若要创建和管理配额规则，请打开 **团队设置** 并切换到 **配额** 标签页。
- 若要监控实时用量，请打开 **团队仪表板**，并在 **团队** 区域下选择 **配额**。

配额仪表板面向团队所有者开放。

---

## 作用域模式

创建或编辑配额规则时，可定义限制额度的生效方式：

### 1. 每位成员独立配额 (Each Member)

- **工作机制**：作用域内的每位成员均获得独立的使用额度。单名成员的消耗不会影响其他人的剩余配额。
- **可选角色筛选**：可将配额限定为特定角色的成员（例如仅限 **编辑者 (Editor)** 或 **审阅者 (Reviewer)**），或应用于全团队。
- **适用场景**：为每位编辑者分配每天 100,000 Token 的用量预算。

### 2. 全体成员共享池 (All Members - Shared Pool)

- **工作机制**：所有符合条件的成员共同分摊一个配额总池，每位成员的消耗均从该总额中扣除。
- **可选角色筛选**：将共享池应用于全团队成员，或仅限定特定角色。
- **适用场景**：将团队每天在 AI 模型上的总开销上限控制在 50 美元以内。

### 3. 指定成员 (Selected Members)

- **工作机制**：为选定的个别团队成员分配独立限额。
- **适用场景**：为资深艺术家或技术总监赋予更高的限额，同时对其他人保持标准限制。

## 支持的资源类型

Shumai 在 AI 与智能体架构的多个层级上均支持配额管控：

| 资源类型                                     | 说明                                                                             | 目标范围                        |
| :------------------------------------------- | :------------------------------------------------------------------------------- | :------------------------------ |
| **总 Token 数 (Total Tokens)**               | 在对话、评论与自动填充中消耗的 LLM 输入与输出 Token 总数。                       | 团队、角色或成员                |
| **AI 成本 ($) (AI Cost ($))**                | 调用 AI 模型服务商产生的美元费用开销。                                           | 团队、角色或成员                |
| **MCP 服务调用次数 (MCP Server Calls)**      | 发送给已连接模型上下文协议 (MCP) 服务的工具调用总数。                            | 目标 MCP 服务 ID                |
| **沙箱 Bash 命令 (Sandboxed Bash Commands)** | 智能体在隔离沙箱内执行的 Shell 命令。                                            | 通配符模式（例如 `npm *`、`*`） |
| **智能体工具调用 (Agent Tool Calls)**        | 对特定原生工具的调用次数（例如 `read_asset`、`download_asset`、`create_file`）。 | 工具名称                        |

### Bash 命令通配符匹配

在沙箱 Bash 执行中，支持使用通配符（`*` 与 `?`）限定特定的命令模式：

- `*`：匹配任意 Bash 命令执行。
- `npm *`：匹配任意 npm 命令（例如 `npm install`、`npm test`）。
- `git commit*`：匹配 git commit 相关调用。

## 时间周期与滚动重置

配额支持配置以下重置周期：

- **1 小时** (`1hour`)
- **5 小时** (`5hour`)
- **1 天** (`1day`)
- **7 天** (`7day`)

### 惰性重置机制

Shumai 自动跟踪用量周期窗口。当周期窗口到期后，系统会在成员发起下一次请求时自动重置配额并开启新的周期，无需后台定时巡检任务即可无缝衔接。

## 监控实时用量

团队所有者可在团队仪表板中查看实时消耗情况：

1. 打开 **团队仪表板**。
2. 在 **团队** 区域下选择 **配额**。
3. 配额规则以一级折叠卡片形式展示。
4. 展开某条规则以查看其用量明细记录。

每条用量记录包含以下信息：

- **消耗状态**：显示已用额度与总额度对比的进度条。
- **剩余可用量**：剩余额度的百分比与具体数值。
- **刷新倒计时**：当前活跃周期重置前的剩余时间（例如：_“45 分钟后刷新”_）。
- **目标对象**：与该记录关联的团队共享池、角色池或具体成员。
- **成员搜索**：对于成员级别的规则，支持按成员姓名或邮箱搜索用量记录。

展开规则时会加载用量记录，且在规则展开期间保持自动刷新。

### 手动重置用量记录

每条用量记录均包含 **重置用量** 操作项。确认操作后：

- 消耗量归零。
- 配额新周期立即开始。
- 该周期在达到设定的配额时长后结束。
- 例如，在 10:00 重置一个 1 天配额，将开启从 10:00 至次日 10:00 的全新周期窗口。

重置操作还可用于为尚未产生用量的成员或共享池初始化一条用量为零的记录。重置行为会记录在团队审计日志中。

## 管理配额规则

- **启用 / 禁用**：通过切换团队设置中任意配额卡片上的开关，可在不删除规则的情况下临时暂停或恢复执行。
- **编辑规则**：点击团队设置中的任意配额卡片，即可更新限额、更改重置周期或调整选定的成员。
- **删除规则**：打开团队设置中的卡片操作菜单（`⋮`）并选择 **删除**，即可移除该配额规则。

配额用量的监控与重置在团队仪表板中操作，而非在设置规则卡片中处理。
