运行自动化脚本存在潜在的安全风险。Shumai 通过在安全且隔离的**沙箱（Sandbox）**环境中执行所有智能体技能来化解这一隐患。

---

## 沙箱安全机制

沙箱严格限制执行进程访问宿主机文件系统、系统进程及内部网络：

- **环境隔离**：脚本在虚拟化的工作区容器中运行，无法篡改系统核心文件或读取其他项目数据。
- **网络桥接管控**：来自沙箱内部的外部网络请求会受到严格监控。

### 文件系统访问限制

为保障工作区环境与敏感数据安全，沙箱实施了严密的文件级访问控制策略：

- **读取权限**：沙箱允许读取工作区内的普通文件，但严格禁止访问敏感环境配置与证书密钥文件。禁止读取的文件模式包括：`['.env', '.env.*', '*.pem', '*.key']`。
- **写入权限**：沙箱的写入权限受到极为严苛的限制，仅允许写入当前工作目录（cwd）下的 `.pi` 文件夹。即便在该受信任的目录内部，沙箱也严禁写入或创建匹配以下模式的敏感文件：`['.env', '.env.*', '*.pem', '*.key']`。

## 域名白名单

默认情况下，网络沙箱处于**关闭**状态（允许所有出站网络请求）。团队所有者可在沙箱设置中开启网络沙箱，以强制推行严格的域名白名单管控：

### 允许的域名 (Allowed Domains)

允许沙箱内脚本正常访问的域名清单。

- 默认白名单包含标准软件包注册表（如 npm、Python 官方源等）以及代码托管平台（如 `github.com`）。
- 若脚本需要调用外部 API（如 `api.slack.com`），管理员须预先将其添加至白名单中。

### 待审批域名 (Pending Domains)

当智能体脚本尝试访问未经授权的域名时：

1. 网络连接将被即刻拦截。
2. 系统会记录目标域名并将其加入**待审批域名**列表。
3. 管理员可审阅该列表，点击**批准**将其加白，或点击**拒绝**保持拦截。
