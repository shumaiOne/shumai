---
title: 邮件通知
description: 配置团队 SMTP 设置，发送聚合活动摘要邮件，并执行测试邮件发送。
---

Shumai 内置邮件通知系统，可将团队动态（如评论、@提及、新资产上传、状态变更以及看板任务更新）直接推送到团队成员的邮箱中。

为避免收件箱泛滥及通知疲劳，Shumai 不会针对单次操作即时发送零散邮件。后台投递服务会自动聚合待发送的通知，并定期发送包含内联缩略图与深度链接的批量摘要邮件。

---

## 配置 SMTP 设置

邮件通知由**团队所有者**在团队层级统一管理。

发送邮件配置步骤：

1. 点击侧边栏的 **团队设置**。
2. 选择 **邮件通知** 标签页。
3. 开启 **启用邮件通知** 开关。
4. 填写 SMTP 服务器凭据与发件人信息。
5. 点击 **保存** 或 **保存并发送测试邮件**。

### SMTP 服务器设置

| 字段                          | 说明                                                                                                             | 示例 / 默认值                                    |
| :---------------------------- | :--------------------------------------------------------------------------------------------------------------- | :----------------------------------------------- |
| **SMTP Host**                 | 发送邮件的 SMTP 服务器主机名或 IP 地址。                                                                         | `smtp.example.com` 或 `smtp.sendgrid.net`        |
| **SMTP Port**                 | 连接 SMTP 服务器的端口。                                                                                         | `587`（默认，STARTTLS）、`465`（SSL/TLS）或 `25` |
| **Username**                  | SMTP 服务器身份验证所需的用户名或 API Key。                                                                      | `user@example.com` 或 `apikey`                   |
| **Password**                  | 身份验证密码或 API Secret。                                                                                      | `••••••••`                                       |
| **SSL / TLS (SMTPS)**         | 直接使用 SSL/TLS 加密连接。通常在使用端口 `465` 时需要开启。                                                     | `Disabled`（默认禁用）                           |
| **Ignore Certificate Errors** | 允许使用自签名证书、无效或未验证的 TLS 证书建立连接。适用于本地测试（如 Mailpit、MailHog）或企业内部中继服务器。 | `Disabled`（默认禁用）                           |

> [!TIP]
> **密码保留**：修改现有邮件配置时，若无需更改密码，可将密码输入框留空以保留当前存储的密码。出于安全考虑，系统绝不会向客户端明文返回已保存的密码。

### 发件人信息

| 字段         | 说明                                                                                         | 示例 / 默认值                  |
| :----------- | :------------------------------------------------------------------------------------------- | :----------------------------- |
| **From**     | 显示在邮件 `From` 标头中的发件人姓名与邮箱地址。请确保 SMTP 服务商已授权代表此地址发送邮件。 | `Shumai <noreply@example.com>` |
| **Reply-To** | _(可选)_ 成员直接回复通知邮件时接收回复的邮箱地址。                                          | `support@example.com`          |

## 测试 SMTP 投递

在正式启用邮件投递前，可直接在设置页面验证配置与凭据：

1. 点击 **保存并发送测试邮件**。
2. 在 **发送测试邮件** 弹窗中，核对或调整发件人 `From` 地址。
3. 点击 **发送测试邮件**。

Shumai 将向 SMTP 服务器发起主动握手验证（`transport.verify()`），并向当前登录的管理员邮箱发送一封样式精美的测试邮件。

若握手或投递失败（例如密码错误、出站端口受阻或发件人地址被拒），界面将弹出 Toast 提示并显示 SMTP 服务器返回的具体错误信息。

## 投递架构与摘要批量聚合

Shumai 采用异步批量架构投递邮件通知：

```
[ 团队活动 ]
(评论、上传、@提及、看板)
        │
        ▼
[ 数据库队列 ] (状态: pending)
        │
        ▼ (每 3 分钟)
[ 通知后台任务 ]
        │
        ├─ 筛选接收者（检查用户偏好与项目范围）
        ├─ 排除本人操作与 AI 智能体
        ├─ 分组与折叠条目（超过 3 项自动聚合汇总）
        ├─ 拉取头像与缩略图作为内联 CID 附件
        │
        ▼
[ Nodemailer 传输层 ] ──> SMTP 服务器 ──> [ 成员收件箱 ]
```

### 1. 定期后台投递

通知在 PostgreSQL 中以 `pending` 状态入队。后台任务每 **3 分钟** 定期运行一次，通过原子队列锁（`FOR UPDATE SKIP LOCKED`）获取待处理通知。即便多实例并发运行，也能确保安全投递且不产生重复邮件。

### 2. 摘要汇总打包

系统不会在每次操作发生时立即发送邮件，而是在 3 分钟窗口期内收集属于同一接收者的所有通知，并将其合并为单封摘要邮件。这既能保持团队协作沟通条理清晰，又避免了高频协作时的收件箱骚扰。

### 3. 智能活动折叠

当某个事件集包含大量条目时（例如剪辑师一次性上传数十个视频片段），Shumai 会自动对其分组并折叠：

- 若分组中包含 **3 项或更少** 条目，则逐项展示各自的缩略图与详细信息。
- 若一次性上传 **超过 3 项**，Shumai 会将其汇总为单条简明通知（例如：_“Alice 向项目 Project Alpha 上传了 12 个新文件”_），并附带前三个文件名的预览。

### 4. 内联 CID 附件

系统从存储中提取头像及视频/图片资产缩略图，以 MIME 内联附件（`cid:...`）的形式直接嵌入邮件中。

与外部图片链接相比，内联 CID 附件具备以下优势：

- 在桌面端及移动端邮件客户端（如 Apple Mail、Gmail、Outlook）中可直接显示，不受“显示远程内容”安全警告的阻拦。
- 无需依赖公开可访问的 S3 URL 或反向代理鉴权即可正常渲染。

### 5. 深度链接

邮件中的每个通知卡片均包含深度链接操作按钮（如 **查看资产**、**查看项目** 或 **查看任务**），成员点击后可直达 Shumai 中的对应资源。

为确保链接跳转至公网域名而非 `localhost`，请在 Shumai 服务器上配置 `APP_URL` 或 `BETTER_AUTH_URL` 环境变量：

```bash
APP_URL=https://shumai.example.com
```

## 成员偏好与过滤机制

邮件投递严格遵循团队权限设定与成员自主偏好：

- **个人偏好**：团队成员可通过 **团队设置 > 通知** 自主选择接收的活动类型。若用户关闭了某分类（如普通评论或状态更新）的通知，Shumai 不会将该类条目纳入其邮件摘要中。
- **自身操作过滤**：成员绝不会收到关于自己发布的评论、上传或任务更新的通知邮件（除非显式开启 **您的上传** 偏好，以便在自身媒体转码完成时获取提醒）。
- **项目范围限制**：权限受限于特定项目的成员，仅会收到其所属项目内的活动邮件摘要，除非他们被显式 `@提及`。
- **AI 智能体过滤**：系统自动将 AI 智能体账户排除在邮件通知接收人之外。
